<objective>
Fix test fixture ordering fragility by updating the shared conftest.py `db` fixture so all committed rows are rolled back at test teardown, and TestClient API calls share the same transaction scope as direct db writes.

Purpose: `creator_user` and similar conftest fixtures commit rows via the `db` fixture. Those committed rows survive into the next test because `db.close()` does not roll back. When pytest-randomly reorders tests, a second test sees rows from the previous test's `db` session and hits UNIQUE constraint errors.

A second problem: `test_bulk_skips_cached_slides` calls `db.commit()` to set `slide_obj.narration_script_hash`, then makes an API call via TestClient. The old `override_get_db` created an independent `TestingSessionLocal()` session that could not see the committed row inside the outer transaction — so `skipped_cached` was always 0.

The fix wraps the `db` fixture in a connection-level transaction + SAVEPOINT AND overrides `get_db` with the same connection, so direct db writes and TestClient API calls are in the same transaction scope.

Output: Updated conftest.py `db` fixture using the connection+nested-transaction+rollback pattern with same-connection get_db override. pytest-randomly added to requirements.txt.

Note on SQLAlchemy version: requirements.txt pins `sqlalchemy==2.0.23`. In SA 2.0, `Session(bind=connection)` is deprecated (emits a warning) but NOT yet removed — removal is planned for SA 2.1. The pattern below works correctly in 2.0.x, producing at most a deprecation warning which can be suppressed if needed.
</objective>

  <files>backend/tests/conftest.py</files>
  <action>
    Two problems to fix in one change to the `db` fixture:

    1. UNIQUE constraint bleed: `db.close()` does not roll back committed rows. When test A commits `creator_test@example.com`, that row persists into test B's session. Fix: wrap in connection-level transaction + SAVEPOINT.

    2. Transaction isolation gap: `override_get_db` creates an independent `TestingSessionLocal()` session. When a test calls `db.commit()` then hits the API via TestClient, `override_get_db`'s separate session cannot see those committed rows (they live inside the SAVEPOINT boundary). Fix: override `get_db` inside the `db` fixture using the same connection.

    Replace the `db` fixture in `backend/tests/conftest.py` with:

    ```python
    @pytest.fixture
    def db():
        """Per-test DB session. All writes are rolled back at teardown.

        Uses a connection-level outer transaction + SAVEPOINT so that even
        explicit db.commit() calls inside fixtures are undone after each test.
        This prevents state bleed between tests when pytest randomises order.

        Also overrides the FastAPI get_db dependency to use the SAME connection,
        so TestClient API calls and direct db queries share the same transaction
        scope — ensuring committed rows are visible across both within one test.
        """
        connection = test_engine.connect()
        outer_tx = connection.begin()
        nested = connection.begin_nested()  # SAVEPOINT
        session = TestingSessionLocal(bind=connection)

        @event.listens_for(session, "after_transaction_end")
        def restart_savepoint(session, transaction):
            nonlocal nested
            if transaction.nested and not transaction._parent.nested:
                nested = connection.begin_nested()

        def override():
            yield session

        app.dependency_overrides[get_db] = override

        yield session

        session.close()
        outer_tx.rollback()
        connection.close()
    ```

    Add `event` to the existing sqlalchemy import at the top:
