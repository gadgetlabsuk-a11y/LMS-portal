  <name>Task 1: Apply transaction-rollback isolation to test_tts_phase17.py db fixture</name>
  <files>backend/tests/test_tts_phase17.py</files>
  <action>
    The root cause: when pytest randomises test order, the conftest `setup_test_db` autouse fixture (drop_all/create_all per test) can race with other test files' fixture teardown at the SQLite engine level. The fix is a file-local `db_isolated` fixture that wraps each test in a nested transaction (SQLAlchemy SAVEPOINT) so writes are rolled back at teardown — making the test independent of table recreation timing.

    Replace the conftest `db` fixture usage in `test_tts_phase17.py` with a file-local `db_isolated` fixture using this pattern:

    ```python
    @pytest.fixture
    def db_isolated():
        """Per-test DB session with nested transaction rollback for order independence."""
        connection = test_engine.connect()
        transaction = connection.begin()
        session = TestingSessionLocal(bind=connection)
        connection.begin_nested()  # SAVEPOINT

        yield session

        session.close()
        transaction.rollback()
        connection.close()
    ```

    Import additions needed at top of file:
    - `from conftest import TestingSessionLocal, test_engine`

    Update these three function signatures to use `db_isolated` instead of `db`:
    - `def creator_slide(creator_token, creator_course, db)` → `def creator_slide(creator_token, creator_course, db_isolated)`
    - `def test_generate_slide_audio_no_script(creator_token, creator_course, db)` → `def test_generate_slide_audio_no_script(creator_token, creator_course, db_isolated)`
    - `def test_bulk_skips_cached_slides(creator_token, creator_video, db)` → `def test_bulk_skips_cached_slides(creator_token, creator_video, db_isolated)`

    In the body of each function, replace every reference to `db` with `db_isolated`.

    The `creator_slide` fixture uses `db` only in its signature (passes it through to ensure table setup ordering). Update the signature only — no body reference.

    The `test_generate_slide_audio_no_script` test uses `db` only in its signature for the same ordering reason — update signature only.

    The `test_bulk_skips_cached_slides` test uses `db` in its body:
    - `slide_obj = db.query(Slide).filter(Slide.id == slide_id).first()` → use `db_isolated`
    - `db.commit()` → use `db_isolated`

    Do NOT touch any other test functions, fixtures, imports (other than the `from conftest import` addition), or logic. This is a targeted fixture isolation fix only.

    Note: `TestingSessionLocal` in conftest.py uses `autocommit=False, autoflush=False, bind=test_engine`. The `bind=connection` override on the session constructor ensures the nested-transaction session operates on the same connection as the SAVEPOINT, so the rollback correctly undoes all writes.
