<objective>
Fix test fixture ordering fragility by updating the shared conftest.py `db` fixture so all committed rows are rolled back at test teardown. This fixes isolation for ALL test files, not just TTS.

Purpose: `creator_user` and similar conftest fixtures commit rows via the `db` fixture. Those committed rows survive into the next test because `db.close()` does not roll back. When pytest-randomly reorders tests, a second test sees rows from the previous test's `db` session and hits UNIQUE constraint errors. The fix wraps the `db` fixture in a connection-level transaction + SAVEPOINT so all commits are local to the test and rolled back at teardown.

Output: Updated conftest.py `db` fixture using the connection+nested-transaction+rollback pattern. pytest-randomly added to requirements.txt.

Note on SQLAlchemy version: requirements.txt pins `sqlalchemy==2.0.23`. In SA 2.0, `Session(bind=connection)` is deprecated (emits a warning) but NOT yet removed — removal is planned for SA 2.1. The pattern below works correctly in 2.0.x, producing at most a deprecation warning which can be suppressed if needed.
</objective>

  <name>Task 1: Fix conftest.py `db` fixture with connection+transaction+rollback isolation</name>
  <files>backend/tests/conftest.py</files>
  <action>
    The root cause of UNIQUE constraint failures under randomised test order is in the conftest `db` fixture. `db.close()` does not roll back committed transactions. When test A's `creator_user` commits `creator_test@example.com`, that row persists into test B's `setup_test_db` (which does `drop_all/create_all` but if timed poorly) or into another `db` session that also tries to create the same user.

    Replace the `db` fixture in `backend/tests/conftest.py` with a connection-level transaction+SAVEPOINT pattern that rolls back all writes at teardown:

    ```python
    @pytest.fixture
    def db():
        """Per-test DB session. All writes are rolled back at teardown.

        Uses a connection-level outer transaction + SAVEPOINT so that even
        explicit db.commit() calls inside fixtures are undone after each test.
        This prevents state bleed between tests when pytest randomises order.

        Note: Session(bind=connection) is deprecated in SA 2.0 but still
        functional — removal is planned for SA 2.1. Suppress the warning with
        filterwarnings if needed.
        """
        connection = test_engine.connect()
        outer_tx = connection.begin()
        nested = connection.begin_nested()  # SAVEPOINT
        session = TestingSessionLocal(bind=connection)

        @event.listens_for(session, "after_transaction_end")
        def restart_savepoint(session, transaction):
            """Re-open SAVEPOINT after each commit so the outer rollback still works."""
            nonlocal nested
            if transaction.nested and not transaction._parent.nested:
                nested = connection.begin_nested()

        yield session

        session.close()
        outer_tx.rollback()
        connection.close()
    ```

    This requires adding one import at the top of conftest.py:
    ```python
    from sqlalchemy import event
    ```

    The `after_transaction_end` listener restarts the SAVEPOINT after each `db.commit()` call so the session remains usable for the full test duration while the outer transaction (which never commits) is rolled back at teardown.

    Do NOT change any other fixture, the `setup_test_db` autouse fixture, `override_get_db`, or `TestingSessionLocal`. Only the `db` fixture and the new `event` import change.

    Also suppress the SA 2.0 `bind=` deprecation warning by adding a `filterwarnings` entry to `pytest.ini` or `pyproject.toml` if the project has one. If neither exists, skip this — the warning is cosmetic and does not affect test results.
